# 添加内容

> 建立内容模型与内容条目，让页面从后台读取数据。

## 先建数据类型

| 项目 | 说明 |
|------|------|
| 菜单路径 | 站点后台 -> 内容 -> 数据类型 |
| 深链 | `/_Admin/contents/types?SiteId={站点GUID}` |
| 详细文档 | [CMS：数据类型](../cms/content/content-types.md) |

数据类型决定内容字段。第一次建议从简单模型开始：

| 场景 | 字段建议 |
|------|----------|
| 新闻 | 标题、摘要、封面、正文、发布日期 |
| 产品展示 | 名称、图片、简介、价格、排序 |
| FAQ | 问题、答案、分类、是否置顶 |

## 再建内容文件夹

| 项目 | 说明 |
|------|------|
| 菜单路径 | 站点后台 -> 内容 -> 内容 |
| 深链 | `/_Admin/contents?SiteId={站点GUID}` |
| 详细文档 | [CMS：内容列表](../cms/content/contents-folders-list.md) |

内容文件夹把一个数据类型变成可维护的数据集合。创建后进入文件夹，添加几条内容作为页面测试数据。

## 在页面中使用内容

| 方式 | 适合场景 | 文档 |
|------|----------|------|
| 模板绑定 | 页面直接渲染列表、详情、字段 | [模板绑定语法](../templateEngine/binding/index.md) |
| `k-data` | 在模板中声明查询、映射与导出 | [k-data](../templateEngine/k-data/index.md) |
| KScript API | 前端通过 JSON 接口读取内容 | [k.content](../api/content/index.md) |

如果你还不准备写脚本，优先用模板绑定或 `k-data`；需要筛选、分页、权限或跨端数据时，再写 API。

## 常见检查

| 问题 | 检查位置 |
|------|----------|
| 页面没有数据 | 内容文件夹是否已有内容，字段名是否与模板一致 |
| 字段显示不对 | 数据类型字段类型、必填、默认值 |
| 列表顺序不对 | 内容条目的排序、发布时间或查询条件 |
| 多语言内容缺失 | 内容语言与站点语言设置 |
