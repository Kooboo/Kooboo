# AI Task Job Prompt Compiler

本文件用于把用户自然语言需求编译成长期运行的 `AITaskJob.Prompt`。当任务复杂、会写入站点、涉及外部数据源或需要精确 Kooboo API 术语时读取。

## 编译原则

1. **不要复述口语需求**：把“每天自动发帖”改写成可执行流程。
2. **先 grounding 后编译**：先确认 Kooboo 能力、函数 schema、KScript reference，再写 prompt。
3. **写入边界显式化**：允许什么、禁止什么、跳过条件是什么，都写入 prompt。
4. **让 job 自主运行**：job prompt 不能要求运行时询问用户；需要用户决定的内容必须在创建 job 前问清楚。
5. **减少运行时探索成本**：在 prompt 中写明应加载哪些 skill/reference、应发现哪些函数、应优先使用哪些对象或路径。

## 推荐 prompt 结构

```markdown
你是 Kooboo 站点的 [任务类型] 自动化任务。请独立执行，不要向用户提问。

## 目标
[一句话说明最终结果]

## 允许范围
- [允许创建/更新/读取的对象]
- [允许使用的外部来源或站内路径]

## 禁止事项
- [禁止删除/覆盖/修改的对象]
- [禁止在数据不足时强行发布]

## 知识与工具准备
1. 调用 load_skill("kooboo-coding")。
2. 根据任务读取必要 reference：[列出 reference 名称]。
3. 调用 function_discover 和 use_function 获取所需函数 schema，不要猜参数。

## 执行步骤
1. [读取数据或外部来源]
2. [过滤、去重、校验]
3. [生成或修改内容]
4. [写入或发布]
5. [记录/汇报结果]

## 质量门槛
- [内容质量、来源数量、去重规则、最小数据量]

## 失败处理
- [外部请求失败、无数据、schema 不匹配、写入失败时怎么做]

## 完成
最后必须调用 ai_task_finish，Message 不超过 50 词。
```

## 边界澄清清单

### 发布类自动化

- 发布到哪里：论坛分类、内容文件夹、Page、API、第三方接口。
- 内容来源：外部 URL/API、站内内容、固定主题、AI 生成、混合。
- 发布策略：直接发布、保存草稿、还是只生成待审核内容。
- 去重策略：URL、标题、slug、发布时间窗口、已有内容查询。
- 质量门槛：最少来源数、必须引用来源、标题格式、字数、标签、封面。
- 禁止事项：不得改旧帖、不得删帖、不得改分类、不得在来源不足时强发。

### 同步类自动化

- 源系统和目标对象。
- 增量规则：按时间、id、etag、hash、标题或 URL。
- 冲突策略：跳过、覆盖、追加版本、只更新空字段。
- 失败策略：局部失败是否继续；是否输出 Warning。

### 清理或更新类自动化

- 精确对象范围。
- 是否允许删除；若允许，删除前是否需要备份或只标记。
- 更新字段白名单。
- 回滚或人工复核方式。

### 巡检和报告类自动化

- 是否只读。
- 报告对象和优先级规则。
- 是否需要发送、保存或发布报告。

## 论坛自动发帖示例

用户口语需求：

> 我想要一个每天自动发帖的任务。

创建 job 前应先问清：发帖来源、分类、直接发布还是草稿、去重规则、来源不足时是否跳过、标题/正文格式、是否需要封面或标签。

编译后的 prompt 可以类似：

```markdown
你是当前 Kooboo 论坛站点的每日自动发帖任务。请独立执行，不要向用户提问。

## 目标
每天从指定来源收集候选内容，生成一篇符合论坛规范的新帖子，并发布到指定分类。

## 允许范围
- 只允许创建一篇新帖子或草稿。
- 只允许读取必要的站点对象、内容、标签和外部来源。
- 如果需要访问外部 API 或网页，先读取 Kooboo KScript 网络请求文档，并优先使用 k.net.httpClient。

## 禁止事项
- 禁止修改或删除历史帖子。
- 禁止修改站点配置、用户、权限、分类结构。
- 来源不足、重复或内容质量不达标时禁止强行发布。

## 知识与工具准备
1. 调用 load_skill("kooboo-coding")。
2. 若需要外部 HTTP 请求，读取 references/K-Script/index.md 和 references/K-Script/net/httpclient.md。
3. 调用 function_discover，并用 use_function 获取发帖、内容读取、对象读取等函数 schema。
4. 不要猜测函数参数；没有可用发帖函数时，用 Warning 结束并说明缺少能力。

## 执行步骤
1. 读取指定来源，收集候选条目。
2. 按 URL 和标题检查重复内容。
3. 过滤无来源、低质量或重复条目。
4. 生成帖子标题、正文、引用来源和标签。
5. 写入前再次确认目标分类存在。
6. 创建新帖子或草稿。

## 失败处理
- 外部来源不可访问时，用 Warning 结束。
- 有效候选不足时跳过发布，用 Suggestion 汇报原因。
- 写入失败时不要重试创建重复帖子，用 Warning 汇报错误。

## 完成
最后必须调用 ai_task_finish，Message 不超过 50 词，说明已发布、已跳过或需要人工处理。
```

## 术语转换示例

| 用户说法 | prompt 中更准确的表达 |
| --- | --- |
| 抓取接口数据 | 读取 `kooboo-coding` 的 KScript net/httpClient 文档后，使用 `k.net.httpClient` 发起外部 HTTP 请求 |
| 自动发帖 | 发现并使用当前站点可用的发帖/内容创建函数；若没有，明确结束并说明缺少发帖函数 |
| 不要重复 | 按 URL、标题、slug 或已有内容查询做幂等检查 |
| 每天跑 | `Repeat=true`、`Frequence=Day`、`FrequenceUnit=1` |
| 先让我看看 | 创建草稿或保存待审核内容，不直接发布 |
