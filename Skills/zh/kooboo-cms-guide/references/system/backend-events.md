# 站点设置 - 动作 Hook

## 页面用途

- 后台页面：`/system/backend-events`；规则编辑页：`/system/backend-events/edit`
- 动作 Hook 在站点对象或部分电商对象发生受支持的创建、更新、删除及业务动作时执行 KScript。
- 它不是所有后台点击、数据库写入或系统任务的统一审计日志。只有当前系统明确发布的事件类型和实际经过相应事件入口的操作才会触发。

## 事件阶段与范围

- 页面、视图、布局、代码、菜单、HTML 块、内容、Label、脚本、样式、图片、商品和商品分类等对象提供创建前后、更新前后或删除前后的事件。
- 部分电商业务还提供商品复制、订单确认、发货和取消等专用事件。事件列表是可用范围的依据，不能仅凭对象存在于 CMS 中就假定有 Hook。
- Creating、Updating、Deleting 等“进行前”事件在原操作持久化前运行，可以检查或修改当前事件对象；Created、Updated、Deleted 等“完成后”事件在原操作之后运行，不能作为可靠的事务回滚机制。
- 动作 Hook 使用站点后台执行上下文，不是访客请求 Hook。它没有可供访客直接观察的正常页面响应链路，也不应用来处理前台路由未找到。

## 规则与代码

- 每种事件类型保存独立规则。IF 中多个条件全部成立才执行 THEN，否则执行 ELSE；DO 规则直接执行。
- 条件字段由事件类型决定，通常围绕对象名称、正文或事件对象的专属字段。跨事件复制规则时必须重新核对可用字段。
- 顶层规则、嵌套分支和同一 DO 中的代码按顺序执行；前一段代码对事件对象或外部系统的副作用可能影响后续处理。
- 动作 Hook 代码可以读写站点数据和调用外部服务。保存成功不等于代码安全、幂等或下游业务已经成功。

## 启用、保存与删除

- 总开关控制动作 Hook 是否参与后续受支持操作。关闭开关会保留规则，不会补跑或撤销停用期间发生的变更。
- 删除某个事件会删除该事件类型下的全部规则，但不会删除对象、历史站点变更或系统对该事件类型的支持。
- 新建规则和开启开关不会追溯处理已有对象；需要处理历史数据时应使用明确的迁移或批处理流程。

## 错误与事务边界

- 当前动作 Hook 执行入口会隔离未处理异常，原始后台操作不应依赖 Hook 抛错来可靠阻止保存或删除。需要强制业务约束时，应使用对象自身的校验或明确的事务逻辑。
- “完成后” Hook 失败不会自动回滚已经完成的原操作；已经发送的邮件、HTTP 请求或其他外部副作用也不会因关闭或删除规则而撤销。
- 修改后应分别验证进行前和完成后事件、条件命中和不命中、创建更新删除等关键动作，并检查目标数据、外部系统和代码日志，而不是只看后台保存提示。
