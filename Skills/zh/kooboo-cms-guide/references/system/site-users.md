# 站点设置 - 站点用户

## 页面用途

- 后台页面：`/system/siteuser`
- 此页把当前组织中已有的账户加入当前站点，并为其分配一个站点角色。
- 它不是注册用户、邀请新账户、修改密码或维护前台会员资料的页面。可选用户来自当前组织，并排除组织管理员和已经加入本站点的用户。

## 用户与角色

- 添加时必须同时选择一个用户和一个角色。当前站点用户记录只保存一个站点角色，不会把多个角色的权限合并。
- 角色列表包含内置角色和当前站点的自定义角色。角色实际能做什么由“角色权限”页中的功能与动作权限决定，不能只根据角色名称猜测。
- 当前页面没有直接修改既有用户角色的入口。需要更换角色时，应先确认新角色权限，再移除并重新添加该用户。
- 用户名和邮箱来自组织账户资料；此页不会创建邮箱、发送邀请邮件或验证账户是否已完成其他登录设置。

## 权限与前台访问

- 对 CMS 后台操作，非站点所有者的请求会按该用户的站点角色检查具体功能和动作权限。站点或组织所有者拥有独立的管理权限，不依赖列表中的普通站点用户记录。
- 站点用户身份也可用于“仅站点用户可访问”的前台站点类型。加入此列表可以满足该类站点的成员判断，但角色权限页本身不是前台页面或 API 的 JWT 验证规则。
- 添加用户不会自动授予组织级管理权、其他站点权限或前台业务系统中的客户身份。

## 删除边界

- 删除站点用户只移除其与当前站点的成员和角色关系，不会删除该用户的全局账户、组织成员资格、密码、邮箱或其在其他站点的权限。
- 删除后，已有登录凭据本身未必立即失效，但后续需要本站点成员或后台权限的请求将无法再通过对应检查。
- 删除用户不会撤销其此前完成的内容修改、发布、外部调用或其他业务副作用；需要追溯历史时应结合站点日志和具体业务记录。

## 操作建议

- 添加前先按最小权限原则核对角色，不要把“能看到菜单”当作拥有所有编辑或删除权限。
- 删除或更换角色后，应让该用户重新进入后台，并分别验证查看、编辑、删除等关键动作；仅刷新管理员自己的列表不能证明对方权限已符合预期。
