# Kooboo 中的 SPA 路由

## 实际行为

当一个访问地址没有匹配到正常的 Kooboo 路由时，SPA 模式会尝试使用站点的默认首页作为应用外壳：

1. 站点必须存在默认首页。
2. Kooboo 在当前请求上下文中渲染该首页。
3. 浏览器地址保持为用户原本访问的地址。
4. 页面加载完成后，由前端路由决定显示哪个界面。

因此，SPA 模式是“在未匹配地址上渲染默认首页”，不是把用户重定向到首页。

## 对 404 的影响

- 未开启 SPA 时，未匹配地址通常进入常规 404 处理。
- 开启 SPA 且存在默认首页时，该地址可以先得到应用外壳，适合前端路由的直接访问和刷新。
- 同时，真正无效的地址也可能看起来返回成功页面。应用自身应提供未找到页面，否则监控工具和搜索引擎可能无法准确识别失效链接。

## 适合开启的情况

- 站点明确采用单页应用架构。
- 使用 History 路由，并要求深层地址能够直接打开和刷新。
- 默认首页负责加载完整应用和前端路由。

仅仅使用 JavaScript、Vue 或 React，不代表站点一定需要开启 SPA。正常使用 Kooboo 页面路由的多页面站点通常不需要此回退。

## 排查建议

- 深层地址仍然失败时，先确认站点是否有默认首页。
- 确认前端路由本身认识当前地址。
- 无效地址都显示首页时，应在前端增加未找到路由，或关闭不必要的 SPA 模式。
- SPA 回退只处理页面地址，不会修复错误的脚本、样式、接口或图片地址。
