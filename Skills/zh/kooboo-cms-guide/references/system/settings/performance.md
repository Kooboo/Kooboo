# 站点设置 - 性能

## 页面用途

- 后台页面：`/system/settings?name=performance`
- 用于配置脚本和样式压缩、浏览器缓存、图片缓存策略、视频缓存及上传图片转 WebP。
- 修改后应同时验证首次加载、重复访问和资源更新后的表现，不能只看单次页面是否打开。

## JavaScript 与 CSS 压缩

- 开启后，Kooboo 会在输出站内脚本和样式资源时生成更紧凑的内容，以减少传输体积。
- 已经压缩过的脚本，以及部分不适合再次处理的脚本，会跳过重复压缩。
- 这里的“压缩”是内容最小化，不等同于服务器的 Gzip 或 Brotli 传输压缩。
- 如果第三方或旧脚本依赖非常规语法，开启后应测试关键交互；发现异常时先对比关闭后的资源内容。

## JavaScript 与 CSS 浏览器缓存

- 开启后，Kooboo 会为站内脚本和样式地址附加版本信息，并返回长期缓存信息。
- 资源内容更新后，版本随之变化，使浏览器请求新版本；内容未变化时可以复用本地缓存。
- 该设置主要作用于由 Kooboo 管理并正常渲染的站内资源，不会自动控制所有外部 CDN 文件。

## 视频浏览器缓存

- 开启后，Kooboo 管理的视频资源会返回长期浏览器缓存信息，减少重复下载。
- 视频被替换后仍应验证实际访问地址和缓存是否符合预期，尤其是复用同一路径的场景。

## 图片浏览器缓存

- 版本控制模式：Kooboo 在渲染图片地址时加入版本信息，并使用长期缓存。图片更新后，新版本地址促使浏览器重新获取。
- 固定天数模式：浏览器按配置天数缓存图片，到期后再重新请求；此模式不依赖同样的地址版本改写。
- 频繁更新但地址保持不变的图片，更适合版本控制模式。
- 希望缓存周期明确、可预测的资源，可使用固定天数模式。
- 该设置主要针对 Kooboo 管理的站内图片；外部图片由其来源服务器决定缓存策略。

## 自动转换图片为 WebP

- 开启后，Kooboo 会在后续新建或更新受支持图片时尝试转换为 WebP。
- 它不会自动批量重写站点中所有已有图片。
- 不受支持的格式、删除操作或转换失败不会得到“所有图片必然转为 WebP”的保证。
- 启用后应检查透明图片、动画图片、图片质量和前端引用是否符合预期。

## 常见误区

- 内容最小化不等于网络传输压缩。
- 浏览器缓存不会减少第一次下载的体积。
- 长缓存必须配合可靠的版本变化，否则用户可能继续看到旧资源。
- WebP 开关主要影响后续上传或更新，不是历史媒体库的一键迁移。
