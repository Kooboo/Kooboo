# 服务集成 - Database

## 页面用途

- Database 分组保存 MongoDB、MySQL、SQL Server、Redis 等外部数据服务的连接字符串；SQLite 项只控制当前站点本地 SQLite 的外键约束。
- 这些配置供站点运行时代码建立连接，不会把外部数据库导入 Kooboo，也不会在保存时复制、迁移或同步数据。

## 连接与运行条件

- MySQL、SQL Server、MongoDB 和 Redis 都依赖各自格式正确的连接字符串，以及运行 Kooboo 的服务器能够访问目标主机和端口。
- 保存连接字符串不会立即建立并验证连接。通常在 KScript 首次使用对应数据库入口时才创建连接；缺少配置、格式错误、网络不可达、TLS 或账号权限问题会在实际调用时暴露。
- MongoDB 连接字符串未指定数据库名时，系统会使用当前站点派生的默认数据库名；不要因此假定它会连接到 provider 账户中的任意现有业务库。
- SQLite 使用当前站点自己的本地数据库文件，不使用远端连接字符串。切换外键约束不会迁移表结构，也不会自动修复已有不一致数据。

## 与站点数据库选择的区别

- 外部连接配置只是让对应数据库入口可用，不会自动把站点默认关系数据库切换到该 provider。代码明确使用 MySQL、SQL Server、MongoDB 或 Redis 时，才读取相应配置。
- SQL 日志开关属于站点高级设置，不在此页。即使开启 SQL 日志，也不能保证外部 provider 的所有网络、认证或服务端错误都形成完整审计记录。

## 风险与验证

- 连接字符串通常包含账号和密码，应使用最小权限账户并限制网络来源。修改凭证会影响之后新建的连接，但不能撤销已经执行的查询或写入。
- 验证应使用最小只读查询开始，再单独验证写权限、事务、字符集、时区和超时。配置保存成功、列表出现 JSON 或一次查询成功，都不能证明全部业务查询与高并发场景可用。
