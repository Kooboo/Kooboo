# 服务集成 - Payment

## 页面用途

- Payment 分组保存 Stripe、PayPal、微信支付、支付宝、2Checkout、Square、Pay.nl、MoneyBoxs 等支付 provider 的账户密钥和模式配置。
- 此页配置的是 provider 凭证，不是电商结账页的支付方式开关。结账允许哪些方式、订单如何创建和页面如何调用支付，需要在电商设置及业务代码中另行完成。

## 配置与 provider 差异

- 不同支付方式使用不同配置项；例如 Stripe Checkout 与 Stripe Payment Intent 是独立配置，PayPal Checkout 与 PayPal Form 也不是同一个入口。
- 沙箱或测试模式只影响支持该选项的 provider，不能假定所有支付方式都有统一测试开关。测试凭证和生产凭证不可混用。
- 微信支付需要 AppId、商户号、API v3 密钥以及证书和私钥文件；支付宝使用固定 RSA2 和 UTF-8，并根据沙箱开关选择网关。字段保存成功不代表证书匹配、签名正确或商户权限已开通。
- 页面上传的配置文件有较小的前端大小限制，适合证书或密钥文本，不是通用附件存储入口。

## 支付结果与回调

- 发起支付会创建支付请求记录并调用所选 provider。部分方式立即返回结果，部分方式要求跳转、二维码、客户端动作或异步通知。
- provider 接受请求不等于订单已支付；页面跳回成功地址也不能替代签名验证、状态查询或回调处理。
- 系统只有在确认 Paid 状态后才进入支付回调工作流；失败、超时、重复通知和用户关闭页面都需要业务流程正确处理。保存密钥不会自动配置 provider 后台所需的 webhook 或回调地址。
- 支付方式还可能限制支持的货币。凭证正确但货币、金额、国家、回调或订单状态不符合要求时，仍会失败。

## 风险与验证

- 修改或清空密钥只影响后续 provider 调用，不会退款、取消在途支付或改变已有订单状态。
- 上线前应以 provider 沙箱完成创建请求、下一步动作、成功回调、失败回调、重复回调和状态查询，再用小额生产交易验证。后台配置列表显示成功不能作为支付闭环证据。
