# 开发资源 - SPA 多语言

## 页面用途

- 后台页面：`/development/spamultilingual`
- 此页维护 SPA 使用的“翻译键 → 各语言文本”数据。它与普通 CMS 内容多语言和 Label 文案是不同的数据集合。
- 系统通过站点的 SPA 语言数据接口按语言返回键值；请求语言没有值时，会尝试使用该翻译项自己的默认语言。此功能不会自动翻译文案。

## 翻译项与语言设置

- 每个翻译项有一个名称作为键，并保存多种语言的值。页面将当前默认语言显示在首列，但不同历史或导入数据可能存在语言集合不完全一致的情况。
- 编辑翻译项会更新当前页面显示的语言值。空值可能在运行时回退到该项默认语言；默认语言也没有值时，该键不会出现在返回结果中。
- “设置”用于统一调整已有翻译项的语言键。新增语言会为所有现有翻译项增加空值。
- 移除语言会从所有翻译项中删除该语言值，不是暂时隐藏一列。当前界面不允许取消首个默认语言，但调整语言前仍应先导出备份。

## 导入规则

- 导入支持 JSON 文件或直接填写 JSON；顶层键是翻译项名称，每个名称最长 50 个字符，内部对象是语言和值。
- `combine` 只填写现有翻译项中缺失或为空的语言值，不覆盖已有非空文本。
- `replace` 会用导入文件中的非空值覆盖相同翻译项、相同语言的值；空的导入值会被跳过。
- `replace` 不会删除导入文件中没有出现的翻译项，也不会清空文件中没有提供的语言。它是按导入值覆盖，不是整个翻译库的镜像替换。
- 新导入的翻译项会使用其首个语言作为默认语言，并补齐站点已有语言的空值。导入前应保证各项语言代码和默认语言顺序符合预期。

## 导出、运行与验证

- “导出全部”和“导出选中项”在浏览器中根据当前已加载列表生成 JSON 文件。导出只是数据快照，不会发布 SPA、切换站点语言或修改前台代码。
- 删除翻译项会删除该键的数据，不会自动扫描或修复 SPA 代码中的引用。前台继续读取被删除的键时，可能得到缺失值。
- 修改后应访问真实 SPA，并分别请求目标语言、缺失翻译语言和默认语言，验证键名、回退结果和前端加载逻辑。后台表格显示正确不等于 SPA 已经使用正确语言地址或已刷新自己的缓存。
