# 开发资源 - 代码

## 页面用途

- 后台列表：`/development/code`；编辑器：`/development/code/edit`。
- 此页集中管理可执行的 KScript 资源。当前可创建的类型包括 API、页面脚本、支付回调和代码块；不同类型的触发方式并不相同。
- 类型筛选只是查看不同代码资源，不能把所有类型都当成可直接访问的 HTTP API。

## 类型与运行入口

- API 拥有站点 URL，通过访问该路由执行。创建 API 会建立对应路由；修改 API URL 会改变该运行入口。
- 页面脚本需要被页面、布局或视图引用后，才会在相应渲染位置执行。保存页面脚本不会自动把它插入任何页面。
- 代码块用于被其他代码导入或调用，本身通常没有独立访问 URL。保存代码块不代表任何页面或 API 已经使用它。
- 支付回调用于支付流程中的回调执行。仅保存回调代码不能证明支付渠道、回调地址和订单状态流转已经配置成功。
- 已有代码的名称，以及部分类型相关选项，在当前编辑界面中不能直接修改；代码类型也不应在创建后被当作普通字段随意转换。
- 无法解密的受保护代码会以错误状态显示，当前编辑器不会提供保存入口；不能把看不到源码解释为代码为空或可安全覆盖。

## API 路由、请求与文档

- API 的 URL 必须可用且不能占用其他有效站点资源的路由。更换 URL 后，旧地址和外部调用方不会自动获得兼容保证。
- API 的请求方法、参数位置、请求体和返回结构取决于代码实际如何读取请求并写入响应；保存时不会替你验证所有真实请求组合。
- API 设置中的 Swagger 开关用于生成和展示接口文档。令牌位置和名称用于描述文档中的认证方式，不会自动实现真实鉴权逻辑。
- 若 API 需要访问控制，应另外配置身份验证规则或在代码中实现校验；JWT Secret 也需要在服务集成中单独配置。

## 保存、执行与排错

- 保存成功只证明代码资源和必要的 API 路由已持久化，不证明代码已经执行成功。
- API 应通过真实 URL、正确方法和代表性输入验证；页面脚本应在引用它的页面验证；代码块应通过实际调用方验证。
- 运行时异常可能导致 API 返回错误状态，并记录为代码错误。排查执行问题时应查看“代码日志”，而不是只看编辑器保存提示。
- 编辑器中的格式化和类型提示有助于编写代码，但不能替代运行时依赖、权限、数据和外部服务验证。

## 共享与删除风险

- 页面脚本和代码块可能被多个资源或其他代码复用。修改共享代码会影响所有调用方。
- 列表中的“被使用”信息主要覆盖 Kooboo 已识别的关系；动态导入、按名称查找或外部 HTTP 调用不保证全部显示。
- 删除 API 会使对应入口不可用；删除页面脚本或代码块可能使引用方渲染或执行失败。删除前应搜索调用方，并在删除后验证主要运行路径。
