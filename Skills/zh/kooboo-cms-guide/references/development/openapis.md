# 开发资源 - Open API

## 页面用途

- 后台列表：`/development/openapis`；定义编辑器：`/development/openapi/edit`；授权页：`/development/openapi/authorizes`。
- 此页把外部服务的 OpenAPI 描述保存为站点资源，使 KScript 可以按描述中的操作调用远程 API。
- 它管理的是远程 API 客户端定义，不是 Kooboo 站点自身 API 的 Swagger 文档，也不会为站点创建公开路由。

## 文档来源与地址

- 创建时可从 URL 下载 OpenAPI 文档、直接粘贴 JSON，或选择远程模板。保存时会解析并规范化为 OpenAPI 3 文档；无效文档或不可访问的 URL 会导致保存失败。
- 创建后，当前编辑器不会让用户直接更换名称或来源类型；编辑重点是当前定义的地址、Base URL、缓存和自定义请求代码。
- URL 类型保存时会下载一次文档；列表中的“更新文档”会重新从原 URL 下载并覆盖当前保存的描述。远程服务后来发生变化，不会在没有更新操作时自动同步。
- Base URL 会优先作为实际调用地址；未填写时，系统尝试使用文档中的服务器地址。文档只提供相对服务器地址时，URL 来源还会参与补全。
- 保存成功只证明定义已保存和解析，不证明远程地址可连接、参数正确、凭据有效或业务调用成功。

## 授权与自定义请求

- “授权”页根据文档中的安全方案维护一组可命名的凭据，支持常见的 Basic、Bearer、API Key 和 OAuth2 数据。调用受保护操作时需要匹配的授权数据。
- OAuth2 挑战会打开外部授权页面，并通过站点回调换取和保存令牌。能打开授权页面不等于授权已经成功；回调地址、客户端配置、范围和令牌端点都必须与远程服务一致。
- 凭据包含密码、客户端密钥和令牌，应按敏感信息管理。删除授权会使使用该授权名称的调用失效，不会自动替换为另一组正确凭据。
- 可启用自定义 KScript，在发送前修改请求的正文、查询参数、路径参数、请求头或 Cookie。代码保存成功不代表每个操作都安全或正确，错误代码可能影响所有使用此定义的调用。
- 编辑器底部保存会持久化整份 OpenAPI 定义并返回列表页；离开前提示不是远程文档备份，也不会替代保存后的真实调用验证。

## 缓存与调用边界

- 缓存规则按请求方法和路径包含关系选择，并以分钟设置过期时间。命中缓存时可能直接返回站点进程内的旧结果，而不再次请求远程服务。
- 缓存键主要由最终 URL 和授权名称组成；对响应强依赖请求正文、请求头或 Cookie 的操作，不应仅凭相同 URL 假定缓存结果可安全复用。
- 缓存不会提高远程写操作本身的可靠性，也不能替代远程服务的幂等、权限和错误处理。
- 实际调用仍可能因网络、远程状态码、文档与服务不一致、参数缺失或令牌过期而失败。验收时必须执行目标操作并核对远程业务结果，不能只看 OpenAPI 定义已存在。

## 删除与变更风险

- 删除 OpenAPI 定义会同时删除它在此处维护的授权记录，但不会自动修复 KScript、页面或任务中的调用。
- 更新文档可能改变操作名称、参数顺序、安全方案或服务器地址。更新前应确认调用方，更新后应重新验证关键读取和写入操作。
