# 开发资源 - 表单数据

## 页面用途

- 后台页面：`/development/form-values?id={formId}`
- 此页查看指定表单保存到站点内部 FormValue 存储中的提交记录，并支持分页查看和删除记录。
- 它不是所有表单提交方式的统一审计日志，也不展示内容写入、站点 API、页面直投、外部地址或其他下游系统的处理结果。

## 哪些提交会出现在这里

- 只有表单启用并选择内部 FormValue 提交方式时，提交字段才会保存为此页记录。
- 选择页面跳转、内容、API 或外部地址等其他提交方式时，其结果不会因为属于同一个表单就自动复制到 Form Values 页面。
- 内部提交会保存表单字段或查询参数中的值，并忽略 Kooboo 自身使用的内部字段；没有可保存字段时不会创建空记录。
- 切换提交方式不会迁移、补齐或重新分类以前的记录。页面为空不能单独证明表单从未被提交，也可能是当前表单使用了其他提交方式。

## 分页、排序与动态列

- 页面只读取 URL 中指定 FormId 的内部记录，并按分页返回；后台会优先展示较新的记录。
- 表格列由当前页记录中实际出现的字段名动态合并。因此不同分页可能显示不同列。
- 某个字段在当前页没有出现，不等于表单从未收集该字段，也不等于字段已从表单定义中删除。
- 修改表单字段不会自动迁移已有提交记录。旧记录可能继续保留旧字段名，新旧结构可同时存在。
- 这里保存的是提交时收到的字段值，不代表这些值已经通过业务校验、反垃圾检查或下游处理。

## 删除边界

- 删除操作只删除选中的内部 FormValue 记录，不删除表单定义。
- 删除内部记录不会撤回已经创建或更新的内容、已经执行的站点 API、已经直投到页面或外部地址的请求及其下游副作用。
- 页面没有把删除理解为跨提交器的统一撤销。需要处理外部结果时，必须到对应下游系统单独核对和处置。
- 删除后应重新加载当前页确认列表状态；不能只凭按钮提示推断其他系统的数据也已删除。
