# 开发资源 - 表单

## 页面用途

- 后台列表：`/development/forms`；HTML 编辑器：`/development/form/edit`。
- 此页管理表单 HTML、表单提交设置和 Kooboo 已保存的表单数据，分为外部表单与嵌入表单。
- 表单的界面结构和提交行为是两部分：编辑表单 HTML 不等于已经配置数据提交目标。

## 外部表单与嵌入表单

- 外部表单是可被多个页面或组件复用的独立表单资源；嵌入表单属于页面、布局或视图等其他站点对象。
- 新建外部表单时可以指定名称；已有外部表单和嵌入表单的名称在当前编辑界面中不能直接修改。
- 修改嵌入表单会影响它所属的站点对象。复制或新建外部表单不会自动替换页面中的现有表单引用。
- 保存表单 HTML 只更新表单结构，不会自动启用提交，也不会自动选择保存位置、API 或外部地址。
- HTML 编辑器中的格式化只调整标记排版，不会自动生成正确的字段名、提交按钮、验证规则或提交设置。

## 提交设置

- 要形成 Kooboo 负责处理的提交闭环，需要启用表单设置并选择提交器。未启用或未选择提交器时，表单仍可能正常渲染，但不能据此认定 Kooboo 会接收和处理数据。
- `FormValue` 把提交字段保存到当前表单的数据列表；“数据”数量和详情只代表这种已写入的表单记录。
- `ContentFolder` 把字段写入指定内容文件夹。字段名、内容类型和多语言值仍需与目标内容结构匹配。
- `Api` 在站点内执行所选 API 代码；API 自身的逻辑、权限、异常和外部依赖仍需单独验证。
- `SubmitToPage` 或 `SubmitToExternal` 会让浏览器直接把表单提交到所选页面或地址，Kooboo 不会替目标页面或外部服务证明处理成功。
- 提交方式可选 GET 或 POST。重定向用于非 Ajax 提交后的跳转；“刷新当前页”依赖提交时携带的当前访问地址。

## 成功边界与数据查看

- 设置保存成功只证明提交配置已保存，不证明访客提交、内容写入、API 执行或外部系统处理成功。
- 当前提交入口在调用提交器后主要依据响应是否结束或是否出现错误状态继续处理；不能只凭浏览器跳转或通用成功响应推断下游业务已经完成。
- “数据”页展示的是当前表单保存到 Kooboo 表单数据存储中的记录，不是所有提交器的统一审计日志。提交到内容文件夹、API、页面或外部地址的数据不一定出现在这里。
- 表单的装配方式以及 HTML 中已有的 `action`、`method` 可能影响最终提交行为。调整设置后应检查前台实际渲染的表单属性和网络请求。

## 删除与变更风险

- 删除表单不会自动修复页面、布局、视图或组件中的引用，也不应假定会同时清理所有历史提交数据和下游数据。
- 删除“数据”页中的记录只删除所选表单数据，不会撤销已经写入内容文件夹、API 或外部系统的结果。
- 修改字段名、提交目标、请求方式或重定向后，应使用真实页面进行一次完整提交，并分别确认浏览器响应和目标系统结果。
