# 开发资源 - 代码日志

## 页面用途

- 后台页面：`/development/code-log`
- 此页查看站点 KScript 主动写入的代码日志，用于排查业务代码执行过程。它不是站点后台操作日志，也不保证收集每一种运行时错误。
- 每条记录包含级别、时间、Trace ID、分类和消息。代码没有写日志、日志功能未启用或日志级别被过滤时，此页不会自动产生记录。

## 启用与记录范围

- 站点级“启用”开关决定新的代码日志是否进入记录流程。启用代码日志不会补录此前没有记录的执行。
- 日志还受站点设置的最低级别限制；低于该级别的消息不会保存。页面中的 All、Debug、Information、Warning、Error、Critical 是对已保存记录的查询条件，不会改变代码的执行结果。
- 日志写入是异步完成的，刚执行完代码时列表可能有短暂延迟。反复查询不会重新执行代码，也不会生成新的日志。

## 周、筛选与检索

- 日志按年和周分区保存，页面最多列出最近 8 个可用周。选择某一周后，时间范围、级别、Trace ID 和关键词都只查询该周已有的数据。
- 时间范围按具体记录时间过滤；级别和 Trace ID 为精确匹配。关键词只在分类和消息中查找，并且是包含匹配。
- Trace ID 可以帮助关联携带同一标识的多条日志，但相同 Trace ID 不等于完整的分布式调用链，也不能证明所有相关系统都已记录。
- 空结果可能意味着周或筛选条件不正确、日志已过保留期、代码没有写日志、日志被级别设置过滤，或写入仍在排队；不能直接得出“代码没有执行”的结论。

## 保留与诊断边界

- 站点具有代码日志保留天数设置，后台会周期性尝试清理过期日志；页面不能恢复已经清除的数据。可选周数也不代表所有历史数据都会永久保留。
- 日志消息由业务代码决定，可能包含请求参数、外部响应或异常详情。写日志时应避免记录密码、令牌、支付信息等敏感数据。
- 排查问题时，应先确认日志开关和最低级别，再选择正确周和时间范围，最后结合前台请求、API 响应或任务执行日志判断实际结果。仅看到一条 Information 日志不等于整个业务流程成功。
