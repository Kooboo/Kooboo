# 开发资源 - 脚本

## 页面用途

- 后台列表：`/development/scripts`；编辑器：`/development/script/edit`。
- 此页管理浏览器加载的脚本资源，分为外部脚本、嵌入脚本和脚本组。
- 这里的脚本是前端 JavaScript 资源，不等于“代码”页中的服务端 KScript、API 或代码块。

## 外部脚本与嵌入脚本

- 外部脚本是拥有站点 URL 的独立资源，可通过预览地址直接查看返回内容。
- 新建外部脚本时默认使用 `.js` 扩展名，并建立对应站点路由。如果输入的路径已经绑定到一个脚本，保存可能更新已有脚本，而不是创建同路径副本。
- 已有外部脚本的名称在当前编辑界面中不能直接修改。若要更换地址，应同时检查所有页面、布局、视图和脚本组中的引用。
- 嵌入脚本属于页面、布局、视图等其他站点对象，不是普通的独立外部脚本。编辑或删除它会影响所属对象中的相应脚本片段。
- 编辑嵌入脚本时不会显示独立脚本的名称表单，因为它的身份和归属来自所属对象；保存是在更新所属对象中的脚本内容。
- 保存脚本不会自动把它加载到任何页面。只有页面、布局、视图或其他资源实际引用它，浏览器才会加载。
- 编辑器格式化只调整 JavaScript 排版，不会执行脚本或验证浏览器兼容性、依赖顺序和业务结果。

## 脚本组

- 脚本组把多个外部脚本的路由按顺序组合为一个可访问资源；它不是把子脚本复制或永久合并成一份新的源代码。
- 子脚本顺序会影响执行顺序。调整顺序后，应验证依赖前置脚本的页面。
- 从组中移除脚本只改变组的组成，不会删除该脚本资源；修改子脚本后，引用该组的页面会使用更新后的内容。
- 脚本组创建后，当前界面不提供直接改名能力；现有页面也不会因为新建或复制一个组而自动切换引用。

## 上传、预览与站点设置

- 上传用于导入 JavaScript 文件。目标位置存在同名脚本时会要求确认，不能假定系统总是保留两个副本。
- 预览成功只证明该脚本或脚本组的资源地址能够返回内容，不证明它已经被页面引用，也不证明浏览器中的业务逻辑运行正确。
- “JS/CSS 压缩”会影响脚本对外返回时的最小化处理；已经最小化的文件和部分特殊工具文件可能跳过再次最小化。
- “JS/CSS 浏览器缓存”影响静态资源缓存行为。调整缓存或压缩后，应使用实际页面和浏览器网络请求验证生效结果。
- 运行时会按 JavaScript 内容类型返回脚本，并支持传输压缩、版本和条件请求；这些行为不等于源代码本身被永久改写。

## 删除与变更风险

- 删除或更换脚本 URL 可能破坏页面、布局、视图、脚本组或自定义代码中的引用。
- “被使用”信息可帮助查看 Kooboo 已识别的依赖，但动态拼接、运行时代码和站外引用不保证能被完整识别。
- 修改共享脚本或脚本组后，应至少验证主要页面的加载顺序、浏览器控制台错误和相关交互。
