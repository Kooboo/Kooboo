# 开发资源 - 身份验证

## 页面用途

- 后台页面：`/development/authentication`
- 此页配置站点前台路由的身份验证规则。规则在已匹配到站点路由、准备执行页面或 API 前运行。
- 身份验证规则不会创建登录页、用户系统或令牌签发流程，也不等于后台管理员权限设置。

## 匹配规则

- Matcher 为 `None` 时，该规则不会匹配；`Any` 会匹配任意进入验证阶段的站点路由；`Condition` 按 URL 或请求方法判断。
- 条件支持等于、不等于、包含、不包含、开头匹配和非开头匹配。比较会忽略大小写，并去除条件两端空白。
- 同一条 `Condition` 规则中的多个条件必须全部成立才会匹配。
- 系统按存储中的规则顺序查找，并使用第一条匹配规则；页面按最后修改时间展示，不代表真实匹配优先级。存在重叠规则时，不能依赖列表显示顺序推断结果。
- `Any` 或过宽的 URL 条件可能覆盖大量页面和 API，启用前应明确排除登录、令牌获取、静态入口或其他必须匿名访问的路径。

## 验证动作与失败处理

- `None` 动作允许请求继续执行；`JwtAuth` 校验请求中的 JWT；`CustomCode` 执行自定义 KScript，并以响应状态判断是否继续。
- JWT 校验会先读取 `Authorization: Bearer ...`，没有时再尝试 `jwt_access_token` Cookie。通过后，后续代码可以读取令牌载荷。
- JWT Secret、有效期等参数不在此页配置，需要在站点“服务集成 → Others → JwtSetting”中单独设置。创建 `JwtAuth` 规则不会自动生成令牌或 Secret。
- JWT 失败时可返回指定 HTTP 状态码、重定向到指定 URL，或输出验证错误。重定向会附带原始地址，目标登录页仍需自行实现返回流程。
- 自定义代码可以直接决定响应状态、内容或重定向。代码保存成功不代表所有请求分支都安全，应使用匿名、有效凭据和无效凭据分别测试。

## 生效范围与验证

- 身份验证只在已经匹配到有效站点路由的前台请求上执行；它不是完整的 404 处理器，也不是后台菜单权限系统。
- 修改规则后，应使用真实域名和真实请求方法测试目标页面或 API。只在后台看到规则不代表运行时匹配符合预期。
- 对 API，应同时验证状态码、响应体、跨域预检和令牌来源；对页面，应验证登录跳转、返回地址和登录后的再次访问。

## 删除与风险

- 删除规则会立即移除相应保护范围，不会自动迁移到其他规则或自定义代码。
- 规则过宽、失败状态错误或重定向地址不当，可能造成整站访问受阻或循环跳转。
- 规则名称创建后在当前界面中不能直接修改。调整或删除前，应记录它实际覆盖的 URL、请求方法和依赖的 JWT/自定义代码配置。
