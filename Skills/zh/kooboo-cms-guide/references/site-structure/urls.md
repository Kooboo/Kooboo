# 站点结构 - URL

## 页面用途

- 后台页面：`/development/urls`
- URL 页面分别管理站点内部路由、站点记录的外部资源地址，以及近期仍无法匹配路由的 Not Found 请求。
- “内部”“外部”和“Not Found”不是同一批数据的简单筛选，而是用途不同的资源和记录。

## 内部 URL

- 内部列表中的每一项是一条站点路由，并显示它指向的页面、脚本、样式、图片、文件或其他目标类型。
- 显示为没有目标对象的路由，表示它当前没有正常绑定的目标资源，通常需要按孤立路由排查；目标类型为路由的项目则可能是指向另一条路由的别名。
- 编辑内部 URL 会改变路由身份，并尝试更新 Kooboo 已识别的引用。动态拼接、脚本生成、外部网站或纯文本中的地址不保证能被更新。
- 普通目标资源所绑定的主路由不能在这里当作独立空链接随意删除；可直接删除的主要是别名或没有正常目标对象的路由。

## URL 别名

- 别名会新增一条指向已有目标的路由，不会复制目标页面或其他资源。
- 原地址和别名可以同时访问同一个目标；修改目标资源时，两条地址看到的是同一份内容。
- 如果目标路由带参数，别名仍需要满足相应参数语义；创建别名不会自动补全业务数据。
- 从 Not Found 记录创建别名，会让该路径今后的请求能够匹配目标路由，但不会创建内容，也不会追溯删除历史日志。

## 外部 URL 与内部化

- 外部列表保存页面、布局或视图引用过的远程脚本、样式、图片等资源地址，它们不是站点内部路由。
- 对脚本、样式或图片执行“内部化”，会把远程资源转换为站点本地资源并更新可识别引用，不只是给 URL 改名。
- 内部化成功后仍应验证资源内容、相对依赖、跨域行为和前台加载结果。
- 删除外部 URL 记录不会删除远程服务器上的文件，也不能保证所有自定义引用都被同步清理。

## Not Found 与清理风险

- Not Found 列表来自近期 404 请求日志，并且只保留当前仍无法解析为站点路由的地址。
- 它用于发现失效入口和创建别名，不等于完整、永久的站点死链扫描报告。
- 删除路由时是否清理已识别引用取决于站点设置；即使开启清理，也不应承诺所有动态或站外引用都能自动修复。
- 修改、别名化或删除 URL 后，应验证主要入口、菜单、多语言地址、静态资源和外部链接。
