# 站点结构 - 布局

## 页面用途

- 后台列表：`/development/layouts`；编辑器：`/development/layout/edit`。
- 布局是可被多个页面复用的完整 HTML 外壳，通常承载文档结构、页头、页脚、公共样式引用和页面内容的装配位置。
- 布局本身不是访客页面，也不会因为创建成功就获得一个普通页面 URL。

## 占位区域

- 布局通过命名占位区域接收页面或视图内容。新建布局默认包含一个 `Main` 占位区域。
- 页面内容必须装配到布局中存在的对应占位区域；名称不一致、占位区域被删除或结构被破坏时，内容可能无法出现在预期位置。
- 一个布局可以包含多个占位区域，用于区分主内容、侧栏或其他装配位置。
- 占位区域只定义“内容放在哪里”，不会自动产生页面内容、菜单或数据查询。

## 名称、复用与复制

- 布局名称是资源的稳定标识。创建后，当前编辑界面不提供直接改名能力。
- 多个页面可以共同使用同一布局。修改共享布局后，所有依赖它的页面都会在后续渲染中使用新结构。
- 列表中的“被使用”信息可用于查看已识别的依赖页面和资源，修改前应先检查影响范围。
- 复制布局会创建一个新的独立布局，但现有页面仍然引用原布局，不会自动切换到副本。

## 编辑与预览边界

- 布局编辑器保存的是可复用外壳；页面的具体正文和页面级配置仍应在页面中维护。
- 编辑器中的格式化只调整 HTML 排版，不会修复占位名称、KScript、资源引用或页面装配逻辑。
- 新建时可以设置布局名称；已有布局的名称在当前编辑器中不可直接修改。
- 保存时，编辑预览所需的基础地址信息不会作为布局正文的一部分长期保留，因此不要依赖它来定义站点实际访问根地址。
- 保存成功只能证明布局资源已更新。公共页头、脚本、样式或占位区域的变化仍应在主要页面上实际预览。

## 删除与变更风险

- 被页面引用的布局不能直接删除。必须先处理引用关系，再执行删除。
- 删除占位区域、改变占位名称或大幅调整 HTML 结构，可能使现有页面的装配内容丢失位置或表现异常。
- “被使用”关系能够覆盖已识别引用，但动态或自定义引用仍应通过站点预览补充验证。
