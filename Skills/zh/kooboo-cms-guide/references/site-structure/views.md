# 站点结构 - 视图

## 页面用途

- 后台列表：`/development/views`；编辑器：`/development/view/edit`。
- 视图是可复用的动态 HTML 片段，可以包含页面标记、数据读取和 KScript 逻辑，并被页面、布局或其他装配位置调用。
- 视图通常负责一个局部功能或展示区域，不是完整页面，也不承担站点首页和错误页等页面职责。

## 预览与页面元素

- 每个视图可以有独立预览地址，用于单独检查渲染结果；独立预览地址不等于公开页面路由，也不会把视图变成普通页面。
- 视图可以启用为页面元素，并设置显示名称、封面和可配置属性，供设计页面选择和配置。
- 页面元素属性可以为视图提供调用时参数和默认值，但不会自动替代视图内部的数据与渲染逻辑。
- 视图名称是稳定标识。创建后，当前编辑界面不提供直接改名能力。
- 编辑器的“设置”对话框维护页面元素信息和缓存选项；在对话框中确认只会把修改带回当前编辑模型，仍需点击页面底部保存才会持久化视图。
- 格式化只调整 HTML 排版，不会验证 KScript、页面元素属性、缓存维度或真实数据结果。

## 缓存行为

- 视图可以缓存渲染结果，并设置缓存时长。
- 如果输出会随设备、语言或查询参数变化，应启用相应缓存维度；遗漏维度时，不同请求可能错误复用同一份缓存结果。
- “按查询参数缓存”只应填写确实影响输出的参数。未列出的变化不会自动进入缓存键，列入过多参数则会降低复用率。
- 按版本缓存可以让相关资源变化参与缓存失效。范围应与视图实际依赖匹配，不能把它理解为自动识别所有动态依赖。

## 复用、复制与删除

- 修改一个共享视图会影响所有引用它的位置，保存后应抽查主要页面和不同参数场景。
- 复制会建立独立的新视图；现有页面和布局仍然引用原视图，不会自动改用副本。
- 列表中的“被使用”信息可以帮助识别引用关系，但动态名称、脚本调用或间接装配不保证全部可见。
- 删除视图前必须检查引用和前台行为；不能假定删除操作会自动修复所有调用位置。
