# 站点运维 - 协作同步

## 页面用途

- 后台页面包括同步连接、待同步变化和远端服务器列表。
- 协作同步连接保存远端服务器地址、远端站点、访问凭证、同步进度以及推送和拉取的忽略范围。它不是 Git 分支，也不是自动三方合并系统。
- 创建连接时，如果尚未指定远端站点，可以在远端创建新站点；此操作依赖远端可达、凭证有效和足够权限。

## Local Changes、Push 与 Pull

- Local Changes 来自当前站点操作日志相对于同步进度的待推送变化，不是对两个站点做完整逐文件或逐对象扫描。
- Push 会真实修改远端站点，Pull 会真实修改本地站点。两者按变化逐项循环，直到远端返回完成，不是一次提交、全成或全败的原子事务。
- 中途失败时，前面已经完成的项目可能已写入目标站点；重试前应重新查看进度和剩余变化，不能假定整个批次自动回滚。
- 推拉成功只证明同步协议处理了相应变化，不代表目标站点已经发布、外部依赖可用或前台业务结果正确。

## 冲突与忽略

- 冲突页可显示本地和远端的用户、时间以及文本或图片内容，供选择处理方式。
- Force Push、Force Pull 和 Ignore Current 分别选择本地一侧、远端一侧或把当前冲突记录为已处理；它们不会自动生成三方合并结果。
- 忽略日志按对象或日志跳过同步，可在之后取消忽略。忽略不会删除本地对象，也不会撤销已经同步到另一端的内容。
- 推送忽略类型和拉取忽略类型是两个独立方向。只配置一个方向不会自动影响另一个方向。

## 设置同步与进度

- 站点设置差异与内容或对象变化是独立入口；Pull Settings 和 Push Settings 需要单独执行，普通对象同步不能证明设置也已一致。
- 同步进度可以手工调整，但它只是游标，不是数据备份。向前修改可能跳过尚未处理的历史变化，向后修改可能让旧变化再次出现。
- 远端差异显示为 0 不一定证明远端没有变化；远端不可达或请求失败时也可能显示 0，应同时检查连接状态和凭证。

## 凭证、服务器与删除

- 协作 Bearer 是带角色和有效期的访问凭证。导入凭证 JSON 用于建立连接，不代表把对方永久加入当前组织，也不代表凭证不会过期。
- Server 列表保存可复用的远端服务器配置。删除服务器条目不会关闭远端服务、删除远端站点或撤销已有同步连接写入的内容。
- 删除同步连接只删除本地连接设置，不会删除远端站点、回滚已同步对象或恢复此前覆盖的数据。
- 执行推拉前应确认方向、目标站点、忽略范围和当前进度；生产站点同步后还需要独立验证发布状态和关键前台路径。
