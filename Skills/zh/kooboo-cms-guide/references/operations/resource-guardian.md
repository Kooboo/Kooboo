# 站点观测 - 资源防护

## 页面用途

- 后台页面包括资源防护概览、防护规则和最近资源日志。
- 此模块观察图片、样式、脚本、文件等站点资源请求，并可按路径、扩展名和来源域名对后续请求执行防护。
- “资源日志”和“网站防护”是两个独立开关：前者控制统计采集，后者控制规则执行。开启日志不会自动开启拦截，开启防护也不等于已有完整统计。

## 资源统计

- 统计按所选日期汇总人类与机器人资源请求、带宽、文件类型、外部来源、失效资源和被防护请求。关闭日志期间的请求不会补录。
- 失效资源表示请求过但未找到的资源，并列出观察到的来源位置；它不是静态依赖扫描，也不能保证发现运行时、站外或未被访问到的引用。
- “正在使用你资源的外部站点”依据请求 Referer 聚合。Referer 可缺失或被伪造，因此它是流量线索，不是域名所有权或侵权证明。
- 资源关系只在系统能识别对应站点路由时提供已知引用信息，不是完整依赖图。删除或修改资源前仍需检查动态 URL、脚本拼接和站外引用。
- 最近资源日志来自内存中的近期循环记录，并由前端分页展示，不是所选日期的完整历史明细或长期审计日志。

## 规则匹配

- 规则保存后按较小的 Priority 值优先检查；第一条同时匹配路径、扩展名和来源条件的规则会执行并停止后续匹配。
- Start Path 是不区分大小写的前缀匹配，可用逗号配置多个前缀，末尾 `*` 只表示该前缀；它不是正则表达式。
- Extension 对去掉点号后的扩展名做不区分大小写的精确匹配。`*` 表示所有扩展名；没有扩展名的 URL只会命中“所有扩展名”规则。
- 域名黑名单为空时，只要路径和扩展名匹配，规则就会作用于所有来源。配置了黑名单时，仅 Referer 主机精确命中其中域名才执行；无 Referer 的请求不会命中该黑名单条件。
- 域名匹配不自动包含所有子域名，也不把路径当作域名的一部分。保存前应分别测试主域、子域、带端口、空 Referer 和伪造 Referer 的情况。

## 防护动作

- Forbidden 对匹配请求返回 403。
- Redirect 对完整 HTTP/HTTPS 地址返回 302；填写站内地址时，系统尝试将其解析为站点路由，找不到目标则返回 404。错误目标或互相跳转可能形成不可用入口或循环。
- 当前界面虽然提供 Watermark 及文字、透明度、字号和位置配置，但当前运行时尚未真正生成水印图片。不要把保存成功或规则命中解释为水印已经生效。
- 防护依赖请求携带的信息，不能替代登录授权、私有存储签名或 CDN 侧安全策略。Referer 防盗链尤其不能视为不可绕过的访问控制。

## 变更边界

- 在规则弹窗中确认只修改页面内的待保存列表；必须点击页面底部保存，规则才会持久化。
- 删除规则或关闭网站防护只影响之后的匹配，不会删除历史日志、恢复已返回的响应或撤销外部站点已经缓存的资源。
- 修改规则后应使用真实资源 URL 分别验证允许来源、禁止来源、空 Referer、不同扩展名和优先级冲突，不能只根据规则列表判断生效。
