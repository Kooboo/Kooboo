# 站点运维 - 站点操作日志

## 页面用途

- 后台页面包括日志列表、对象版本和版本比较。
- 站点操作日志记录站点对象及部分表数据的编辑版本，用于查看修改者、时间、动作和对象历史。它不是登录记录、HTTP 请求日志、KScript 执行日志或系统任务的统一审计日志。
- 列表可按对象类型、动作、用户、时间和名称筛选。筛选只改变当前查看范围，不会删除或修改日志。

## 版本与比较

- Versions 根据同一对象及其存储位置读取历史版本；名称相似但属于不同对象或数据表的记录不会自动合并成一条历史线。
- Compare 可以比较两个历史版本，也可以把一个历史版本与当前最新版本比较。文本对象显示摘要差异，图片对象使用对应版本资源进行图片比较。
- 差异界面说明版本内容不同，不代表其中一侧已经发布、当前仍被引用或业务结果正确。
- 只有存在对应录制数据的日志才可能显示操作视频，不是每条站点日志都有可回放的视频。

## Undo、Restore 与 Checkout

- Undo 或 Revert 针对选中的单个版本或改动回滚对象；Undo Changes 或 Blame 可对选中的多条日志执行回滚。回滚会真实修改当前站点，不是只改变日志显示。
- Restore 从选定日志点整体恢复其后的站点变化，影响范围通常大于单条 Undo。执行前应确认目标时间点、受影响对象和当前未发布修改。
- Checkout 会创建一个独立新站点，把源站在指定日志点的状态恢复到新站点，并将新站点标记为已发布。它不是切换当前站点的代码分支，也不会把当前站点本身退回该时间点。
- Export Changes 和 Export Items 生成临时 ZIP 供下载，不会自动推送到远端、创建同步连接或导入到其他站点。

## Clean Log

- Clean Log 是异步重建操作，不是只删除列表行。执行期间站点会暂时取消发布，当前核心对象和部分附加数据被复制到新存储，旧操作日志被移除，最后恢复原发布状态。
- 页面会轮询清理任务状态。按钮请求成功只表示任务已提交，不代表重建已经完成或站点已经恢复服务。
- 不应假定每种运行环境都一定生成可恢复备份；清理后也没有逐条找回已删除日志的入口。
- 清理期间可能短暂影响前台可用性和后续版本追踪，应在低流量窗口执行，并在完成后核对站点发布状态、关键对象和前台访问。

## 风险边界

- 回滚、整体恢复、Checkout 和清理的作用范围不同，不能把它们当作同一个“撤销”按钮。执行真实写操作前应先导出必要对象或确认已有独立备份。
- 动态引用、外部系统副作用和已经发送的请求不会因为站点对象回滚而自动撤销。日志恢复成功也不等于外部业务状态已恢复。
