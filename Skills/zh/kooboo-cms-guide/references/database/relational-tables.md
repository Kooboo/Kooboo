# 数据库 - SQLite、MySQL 与 SQL Server 表

## 数据源区别

- SQLite 使用当前站点自己的本地 `sqlite.db` 文件；MySQL 和 SQL Server 使用“服务集成 > Database”中保存的外部连接字符串。它们与站点 IndexedDB 是不同的数据源，表和数据不会自动互相同步。
- MySQL 或 SQL Server 缺少配置、连接失败或权限不足时，表页会提示错误并可跳转到 Database 配置。保存连接字符串本身不会证明数据库已经连通。
- 表列表来自当前实际数据库。Kooboo 会同步一份用于后台控件和编辑体验的结构映射，但这不是把外部数据库复制进 Kooboo。

## 表结构与数据

- 新建表会在目标数据库真实创建表，并带有系统使用的 `_id` 主键；业务列需继续添加。删除表会对目标数据库执行删除表操作，并同时移除 Kooboo 的结构映射。
- 已有列名在当前界面不能直接修改。新增、删除列或修改字符串长度会真实执行结构变更；删除列会丢失该列数据。SQLite 调整结构时会重建表并复制新旧结构中仍同名的列，不能把删除再新增当作安全改名。
- 后台根据数据库字段类型映射成文本、数字、布尔或日期等编辑控件。控件映射方便编辑，不等于完整保留每一种 provider 专属类型语义；复杂类型在后台可能按文本处理。
- 数据编辑依赖表的主键定位记录。新建、编辑和删除会直接作用于目标数据库；页面保存成功不代表引用该数据的业务流程、缓存或外部系统已经同步完成。

## CSV 导入与导出

- SQLite、MySQL 和 SQL Server 数据页支持 CSV 导入，单次最多 5000 条。上传后需要映射 CSV 字段与数据库字段，并可标记必填字段和用于查重的唯一字段。
- 缺少必填值的行会被跳过。命中唯一字段的已有记录时，关闭覆盖会跳过该行；开启覆盖才会更新匹配记录。导入只新增或更新映射到的记录，不会删除 CSV 中未出现的数据库记录。
- 导出生成当前表数据的 CSV，不包含内部 `_id`，也不包含表结构、索引、约束、触发器或关系定义，不能替代数据库备份。

## 风险与验证

- 结构修改和删除直接影响真实数据库。操作前应确认 provider 备份、账号权限、字段依赖和停机影响；后台成功提示不能证明触发器、存储过程、应用缓存和外部消费者都仍然正确。
- SQLite 的外键约束由 Database 集成中的单独开关控制；表页面本身不会自动修复已有不一致数据。站点“表关系”页面也不是这三类数据库的外键管理器。
