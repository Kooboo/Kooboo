# 电商 - 通知

## 页面用途

- 后台页面：`/commerce/notification`
- 此页分别配置电商事件邮件和 Webhook，并查看各自的发送日志。
- 邮件与 Webhook 是事件触发后的异步外部通知，不是订单状态、支付状态或下游业务成功的权威来源。

## 邮件通知

- 邮件总开关必须启用，并且事件存在对应模板时才会发送。当前邮件事件包括订单支付、订单取消和订单发货。
- 每个模板可发送给事件中的客户地址，也可发送给额外地址；每个收件地址会形成独立发送和日志结果。
- 可使用 Kooboo 邮件地址或自定义 SMTP。保存服务器和模板不会测试真实连接、额度、账号权限或收件可达性。
- Preview 使用事件的模拟数据渲染主题和 HTML，不会发送邮件，也不证明真实事件数据一定满足模板代码。

## Webhook

- Webhook 总开关必须启用，并且事件存在对应 URL 配置时才会发送。Webhook 事件除订单支付、取消和发货外，还包括客户与购物车相关事件。
- 请求使用 POST 和 JSON 内容，签名是请求正文与站点 secret 拼接后的 SHA-256 小写十六进制值，放在 `X-Kooboo-Hmac-SHA256` 请求头。
- Webhook 请求超时为 15 秒，只有远端返回成功状态码才记为发送成功；这仍不证明远端已经完成业务处理或持久化。
- Secret 用于验签，不是 URL 访问控制。修改 secret 后，接收端也必须同步更新验签逻辑。

## 日志与重试

- 邮件和 Webhook 日志分开分页保存地址、事件、内容、时间、发送状态、错误次数和错误信息；日志不是所有订单事件的统一审计记录。
- 首次发送失败后会先以短延时进入内存重试队列。进入队列后的重试如果再次失败，下一次重试按当前错误次数以小时计算：错误次数 N 就延后 N 小时，不是按秒或按分钟退避。
- 超过一天或错误次数达到限制后不再继续。服务重启、任务服务禁用或站点释放可能使尚未执行的内存重试丢失。
- 邮件发送额度不足不会进入普通重试流程。删除或关闭通知配置不会撤回已经发出的请求，也不会自动删除历史日志。
