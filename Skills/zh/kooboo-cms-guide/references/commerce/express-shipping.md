# 电商 - 实体配送

## 页面用途

- 后台页面：`/commerce/shippings?name=express`、`/commerce/shippings/create`、`/commerce/shippings/edit`
- 实体配送方式定义基础运费、附加费用规则、支持国家、预计到达天数和承运商识别信息。
- 它用于购物车运费计算和后台发货辅助，不会购买物流面单、预约承运商取件或查询真实物流轨迹。

## 运费计算

- 只有购物车包含实体商品时才选择和计算实体配送；纯数字商品订单不使用实体配送费。
- 未找到指定配送方式时，计算可回退到当前默认配送方式。设置新默认项会取消旧默认项的默认状态。
- 运费从基础费用开始，再逐条检查附加费用规则；所有匹配的规则都会累计，不是只取第一条。
- 当前附加费用条件使用商品小计和总重量。总重量来自各变体重量乘数量；重量单位由 Commerce Settings 约定。
- 免运费优惠可以在后续计算中抵消已经算出的配送费，但不会修改配送方式本身的基础费用或规则。

## 国家与承运商信息

- 支持国家和预计到达天数会随配送方式保存并提供给前台使用，但当前运费计算不会据此自动过滤国家，也不会验证真实运输时效。
- Company Code 是配送方式的业务标识；Tracking Number Matching 是正则匹配提示，后台发货时可根据追踪号自动填写承运商名称。
- 这些字段不会自动连接物流 API，也不能证明追踪号有效、包裹已揽收或预计日期能够兑现。

## 修改与删除边界

- 保存成功只证明配送配置已持久化。应以具体购物车、币种、商品重量和小计重新计算验证最终运费。
- 修改费用、规则、国家或默认项不会重算已经创建的订单，也不会修改订单中已经保存的配送金额和发货信息。
- 当前列表不允许直接选择默认配送方式进行批量删除；删除其他配送方式也不会修复前台代码、购物车或历史订单中对它的引用。
