# 整页构图

当组件 prompts 需要形成协调的整页，尤其是视觉表达较强的首页或改版时，按需读取本文。UUPM 组件 prompts 继续作为积木，模型结合用户要求和已确认的 Design System 自主构图。

## 选择有帮助的参考

只在当前页面需要时读取最接近的一类：

- 零售、目录和品牌发现：[商城构图参考](../../../ui-ux-pro-max-pp/references/shop-composition-families.md)
- 出版物与编辑式发现：[杂志构图参考](../../../ui-ux-pro-max-pp/references/magazine-composition-families.md)
- 目录、活动和搜索驱动的发现：[信息入口构图参考](../../../ui-ux-pro-max-pp/references/hub-composition-families.md)

这些是可调整的示例，不要求必须选定一种 family。详情、购物车、结算、账户和表单页优先保证任务与信息层级，不强套首页构图。

## 跨组件组织页面

明确访客首先应该理解什么，并建立一个主要视觉焦点或任务。统一整页的图片裁切、主体位置、标题尺度、色板分配、区块衔接和疏密变化。移动端保留相同层级，确保内容可读、操作可用。构图依赖真实影像时，通过允许的图片路径使用摄影素材。

保留 Page/View 边界、block 顺序、composition groups、必需内容、业务职责、语言、已确认色板和图片/数据/交互策略。把组件 prompt 的视觉建议作为设计素材，结合整页调整视觉表现，同时满足上述要求。Page 承担跨 View wrapper，各 View 完成自己的职责。模型直接将设计决策落实到生成中，无需固定格式说明或额外工具调用。

## 检查结果

关注主次不清、区块割裂、重复等权卡片、图片裁切不佳、标题换行错误，以及移动端丢失任务层级等问题。视觉检查可用且已获授权时使用实际渲染证据；证据不可用时明确标记视觉质量未验证。源码检查和 Preflight 证明的是不同事项。视觉检查不作为对象创建、下一页生成或 capability Preflight 的门禁。
