# 建站能力模块目录

本文用于在 S2 之后生成站点级 milestones，并在阶段完成后筛选下一步推荐。它不是站点类型枚举表；AI 必须根据 Site Brief、Page Plan、用户最近意图和已完成能力裁剪。

## 使用时机

- **S2 停止条件满足后**：读取本文，生成当前站点的首轮 `update_site_milestones`。首轮 milestones 只放当前站点的主干路径和用户已明确要求的能力。
- **阶段完成后**：读取或回忆本文，选择 1-3 个自然下一步推荐，调用 `show_next_recommended_action`。
- **用户采纳推荐后**：把被采纳能力追加或激活为站点级 milestone，并立即为该 milestone 调用 `update_todos` 生成当前阶段待办。

## 筛选顺序

```text
当前阶段
  -> Site Brief
  -> Page Plan / 页面模块
  -> 已完成 milestones / 已完成能力
  -> 用户最近表达
  -> capability.appliesWhen / notWhen
  -> 建立当前站点的能力依赖关系
  -> 输出主干 milestones 或当前依赖前沿
```

### 输出方法

1. **选择能力**：只保留用户最终目标必需、用户已明确要求，或 Page Plan 有直接结构证据的能力。
2. **建立依赖**：把数据、身份、交易、通知等前置关系排成有向主干；同一条链不能伪装成可同时开始的平级选项。
3. **生成 milestones**：通常输出 2-4 个用户可感知结果。使用 Site Brief 中的业务对象和 Page Plan 中的用户路径命名，不直接复制下方内部能力标题或实施检查点。
4. **生成推荐**：先找依赖已满足的未完成 milestone，通常只推荐当前前沿；仅当多个能力互不依赖且都有直接证据时展示 2-3 项。
5. **可选增强**：既定主干完成后，才考虑表单、SEO、邮件、会员等增强；没有证据时不为凑数量推荐。
6. **去重**：若两个候选作用于同一结果或一项是另一项的前置/子步骤，只保留当前可执行且离用户最近的一项。

能力条目中的实施检查点只用于判断范围与依赖，不是可直接复制的 milestones。工具调用、文档读取、预览刷新、设计系统与 Preflight 属于当前阶段 todos 或内部执行，不进入站点路线图。

## 核心能力

### static_delivery

- 标题：静态首版交付
- 适用：所有新建站点和整站静态改造。
- 不适用：仅修复单个对象、只做后端 API、只回答咨询。
- 实施检查点：
  - 确认首版范围与页面结构
  - 交付可预览静态首版
  - 完成静态首版验收

### content_dynamic

- 标题：内容动态化
- 适用：
  - 站点包含博客、新闻、案例、活动、菜单、产品目录、团队、FAQ 等可维护内容。
  - 用户希望后续在后台维护内容。
  - Page Plan 中有列表/详情/分类/筛选/分页等内容结构。
- 不适用：
  - 用户明确只要一次性静态页面。
  - 页面内容极少且无需维护。
- 前置：
  - 静态首版已可预览，或用户明确要求直接动态化。
  - S7 数据源决策完成。
- 实施检查点：
  - 决定内容数据源
  - 确认内容结构草案
  - 接入 SSR 动态内容
  - 完成动态内容验收

### lead_form

- 标题：表单线索收集
- 适用：
  - 站点有联系、预约、报价、试用、报名、询盘、订阅等转化意图。
  - Page Plan 中有 Contact、CTA、Booking、Inquiry、Newsletter 等模块。
- 不适用：
  - 用户明确不收集信息。
  - 只是纯展示且没有联系/转化目标。
- 前置：
  - 表单字段、提交后反馈和通知方式明确。
- 实施检查点：
  - 确认表单字段
  - 创建提交 API 或数据存储
  - 接入前端表单状态
  - 完成表单流程验收

### commerce_catalog

- 标题：商品目录与询价
- 适用：
  - 站点展示商品、服务套餐、菜单、课程、房型、SKU 或价格区间。
  - `commerceModel = catalog-contact`，或用户只需要展示并联系购买。
- 不适用：
  - 用户明确要求在线下单支付，应考虑 `online_checkout`。
  - 站点没有商品/套餐/服务目录。
- 前置：
  - 商品/分类/价格/图片策略明确。
  - Product、Category 和 Variant 默认使用 Commerce；若改用 Content，必须确认它是独立展示目录且不参与 Commerce 交易链路。
- 实施检查点：
  - 确认商品目录结构
  - 接入商品/分类动态数据
  - 接入询价或联系入口
  - 完成商品目录验收

### online_checkout

- 标题：在线下单与支付
- 适用：
  - 用户明确要求在线购买、下单、购物车、订阅、付款或支付。
  - `commerceModel = online-checkout`。
- 不适用：
  - 只是商品展示或联系购买。
  - 用户尚未确认支付方式、币种、订单流程。
- 前置：
  - 商品数据或套餐数据已明确。
  - 支付方式、币种、订单成功/失败路径已确认。
  - 需要读取 commerce 和 payment 相关 reference。
  - 必须读取 `commerce-dynamicization.md`，并把共享 Header 作为顾客状态和购物车状态的必需消费者。
- 当进入 `online_checkout` 交易页面批次时，当前 Page Plan 的最小页面路径：
  - `products`：分类/搜索/排序、商品结果、分页。
  - `product-detail`：商品媒体、变体、数量、可购买状态、加购行动。
  - `cart`：商品行增减删、空状态和金额摘要。
  - `checkout`：联系、地址、配送、支付信息和订单确认。
  - `order-result`：订单与支付成功/处理中/失败/取消状态及恢复行动。
  - `account` / `orders` / `order-detail` / `login` / `register` 按用户会员与订单中心范围加入。
- 该路径是 `online_checkout` 能力的最终页面合同，不是首批静态页面清单。首批范围由 Page Plan 的通用页面角色与预算策略选择；交易和账户页面在对应 milestone/todo 启动后分批生成。
- 实施检查点：
  - 确认下单与支付流程
  - 接入购物车/订单
  - 接入支付 API
  - 完成支付流程验收
- 规划边界：复用 Page Plan v3，并按当前页使用 `page-item` + `view-batch`；页面范围与 prompt 以当前 Page Plan 和按页调用结果为唯一来源。

### member_auth

- 标题：会员与登录
- 适用：
  - 站点需要登录、会员中心、订单记录、收藏、权限内容、用户资料。
  - commerce 用户流程涉及订单、地址、收藏或会员价。
- 不适用：
  - 纯公开展示站点。
  - 只需要一次性表单提交，不需要账号体系。
- 前置：
  - 认证方式已选择。
  - 若为 commerce 用户链路，先读 commerce customer 登录流程。
- 实施检查点：
  - 确认登录方式
  - 创建登录/注册/会员页面
  - 接入会员状态与权限
  - 完成会员流程验收

### multilingual_seo

- 标题：多语言与 SEO
- 适用：
  - 用户面向多个语言市场。
  - 站点需要搜索收录、地区化内容、SEO 标题/描述、结构化内容。
- 不适用：
  - 用户明确只做单语言内部页面。
  - 当前页面内容尚未稳定，不适合先做多语言。
- 前置：
  - 内容语言和目标语言明确。
  - 站点基础页面已稳定。
- 实施检查点：
  - 确认语言与 SEO 范围
  - 接入语言切换和多语言 URL
  - 补齐 SEO 元信息
  - 完成多语言/SEO 验收

### email_marketing

- 标题：邮件营销与通知
- 适用：
  - 站点有订阅、活动提醒、线索跟进、订单通知、验证码、营销邮件。
  - 用户希望沉淀客户联系渠道。
- 不适用：
  - 没有邮箱字段或通知场景。
  - 用户明确不需要消息通知。
- 前置：
  - 邮件用途、触发时机和收件人规则明确。
  - 表单、会员或订单流程至少存在一个触发源。
- 实施检查点：
  - 确认邮件场景
  - 接入邮件发送
  - 接入订阅或通知触发
  - 完成邮件流程验收
