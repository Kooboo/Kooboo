# 站点记忆与会话交接

站点 memory 是当前站点 kfile 的 `_ai/memory/` 目录中的少量 Markdown 记录，入口为 `_ai/memory/index.md`。命名工具在当前站点上下文执行 `scripts/site-development/site-memory.js`，通过 `k.file` 存储；工具 path 参数为该目录下的普通文件名。它用于跨会话上下文，不是第二套规划或进度系统。现有 App 创建、审查、授权和实施门槛继续适用。

## 按当前任务读取

新站点会话先调用 `read_site_memory`，默认读取 `index.md`。入口缺失是正常情况，读取失败不代表不存在。入口响应带有界文件名列表；按索引读取相关文件，或用 `search_site_memory` 搜索字面词组。仅在确实需要时按 `nextOffset` 续读，不重复加载上下文中未变化的记录。

## 在有意义的节点保存

用户要求记住信息，或形成需要长期保留的背景、特殊实现约定及原因、重要资源入口时，调用 `update_site_memory`。先读原文件；使用 `oldContent` 做准确且唯一的局部替换，或用 `content` 更新整份短文并保留无关内容。文件名支持 `index.md`、`inventory.md` 等普通 Markdown 名称。入口不超过 4000 字符，其他文件不超过 24000 字符；需要时才拆分，并从入口引用相关记录。

Topics 管问题、答案和确认，Milestones 管进度，Blueprint/Plan 管各自定义，源码体现实际实现。应按原有授权流程更新这些权威记录，不把它们复制进 memory；可引用稳定 ID 和资源路径。不保存聊天全文、重复工具输出、凭据、临时排查猜测或另一份实施清单。内容转入结构化规划时，确认保存成功，再将重复记忆正文替换成引用。

在重要信息确定时保存，不等会话结束。写入成功会在落库读回后返回 `receipt.path` 和 `receipt.sha256`；哈希只证明保存内容，不证明业务正确。失败时如实说明没有保存。Memory 不覆盖用户当前指示，也不授予实施权限。区分期望行为与当前源码实现。

## 用户主动转到新会话

普通“记住”请求只保存，不新建会话。明确的交接动作会启动仅限记忆操作和相关读取的准备轮；既有记录继续作为权威来源，不在这轮写规划、业务资源或进度。

按需读取并补齐尚未保存的长期信息，然后用 `index.md` 和续作所需文件的最新 `path`/`sha256` 回执调用 `prepare_site_memory_handoff`。读取响应同样返回内容哈希，未变化的记忆不需要重复写。`continuation` 不超过 1500 字符，以用户语言说明当前意图、下一步和必要引用，保留讨论或实施性质及准确授权范围。当前 Milestone 完成不代表下一项已获授权。不嵌入聊天全文或 Topics/Plan 正文副本。先解决保存失败，交接工具最后调用，随后停止。

界面依据结构化结果创建同站点新会话，发送简短续接指令，并保留原会话。本流程不压缩历史，也不处理任意中断恢复。新会话先读入口，再按需读相关权威记录后续作。

## 查看和纠正记忆

AI Chat 设置中的“站点记忆”入口支持读取已有笔记、修改内容和删除文件。管理界面的保存和删除必须携带最新读取的哈希，冲突时重新加载。工具整体替换已有文件时必须传入 `expectedSha256`；也可以用准确且唯一的 `oldContent` 局部替换。不要因为索引仍引用已删除笔记就自动重建它。当前会话中已加载的内容及其他笔记中的引用不会自动移除。

工具保存成功还返回 `siteId`、`savedPreview`（落盘内容前 600 字符）和 `previewTruncated`。聊天界面每次执行只展示一条简短、可点击的保存状态，不展示笔记正文或额外编辑按钮。点击状态可在记忆管理抽屉打开已保存的笔记；也可从 AI Chat 设置进入查看和修改。预览字段是工具结果中的内容节选，不是生成的摘要，也不是当前实现的证据。

保存已经明确的业务背景和特殊约定的原因，不把提议、试验或助手自己的建议升级为已确认的站点约定。正式决定与完成结论仍归属于各自的权威记录。
