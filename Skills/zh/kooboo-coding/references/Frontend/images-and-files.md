# 图片与文件管理

适用于网站、服务端 Page/View、客户端 App 和局部维护。按需阅读：只做展示读配图规则；实现真实上传/文件维护再读保存与清理。保留当前范围、数据策略和静态/动态阶段，不新增规划产物。

## 业务配图

- 内容类业务应展示实际图片字段，例如商品缩略图、文章封面、活动海报；根据任务选择图文行、卡片或图库，不把所有后台都做成纯文字表格，也不为日志/权限页面硬塞装饰图。
- 优先使用已有素材。已有或获准生成的样例记录缺图片时，读取 [ImagePlaceholder](../Functions/image-placeholder.md)，按内容拼接站内 URL，列表/详情使用同一图片字段。真实数据为空时展示诚实的空状态和新增入口，不擅自写入假业务记录；不能用“真实存储”作为省略已有样例配图的理由。
- 设置尺寸/宽高比、object-fit、替代文本和加载失败状态，列表使用合适尺寸。占位图是展示素材，不下载进文件存储，也不参与文件清理。

## 优先使用平台缩略图

`k.file` 和 `k.media` 的站内图片 URL 支持 `?width=320`、`?height=240`，也可同时指定宽高；只指定一边时按原图比例计算另一边。例如 `/__kb/kfile/catalog/photo.jpg?width=320`；媒体库使用其返回的实际图片 URL 添加相同参数。列表/卡片使用少量固定尺寸，放大预览使用原图或更大尺寸；统一裁剪展示用 CSS object-fit，不假设查询参数提供裁剪模式。SVG 直接缩放展示，不依赖此栅格缩略图处理。

保存原始文件标识和原图 URL，在展示时派生缩略图 URL，保留已有查询参数并正确设置 width/height。不把缩略图 URL 当作独立上传资产，不为常规列表缩略图新增 canvas 压缩、后端缩图接口、缩略图表或额外物理文件。平台缩略图缓存由平台管理，业务清理不扫描其内部缓存；业务只管理原文件及自己确实生成的文件。此能力仅用于平台支持的图片地址，不盲目追加到外链、占位图服务或私密下载 API。

## 默认上传方式：保存时上传

普通图片/附件表单默认采用：选择文件 → 本地预览 → 点击保存 → 上传并绑定 → 保存成功。多张商品图片本身不构成提前上传的理由。已有正确的上传实现应复用，不为符合默认方式重写现有流程。

- 使用现有组件的手动上传模式或原生文件控件，提供选择、预览、替换、移除与失败重试，不以粘贴 URL 输入框代替。File 保留在当前表单，Object URL 在替换/卸载时释放，不把 base64 或本地预览 URL 持久化。
- 保存流程拥有上传状态：上传和业务保存全部完成才成功，期间防止重复提交及未处理的离页。子组件上传状态必须传递给保存流程；不能只禁用上传按钮。保存前取消仅释放本地资源，不请求服务端删除未上传文件。
- 优先复用现有服务；当前接口适合时，通过一次 multipart 业务提交处理字段和文件。需要独立上传接口时，保存流程等待所有上传完成再绑定服务端文件标识；失败重试复用仍有效的上传结果，不重复落盘。
- 只有富文本自动上传、大文件/断点续传或跨会话草稿等实际需求才提前上传。此时增加临时归属、TTL、配额和取消释放；不能为了本地图片预览就引入草稿平台、会话接口或多套状态机。

## 保存与清理的最小契约

需要复用 FileIO 保存、转正和临时文件清理原语时，读取可选的[FileIO 工具](../../assets/backend-templates/files/README.md)。它不安装表或 API，不管理业务引用；下述保存与清理契约由调用方负责，静态文件仍遵循站点级访问规则。

编写文件 API 前按需读取 [请求文件](../K-Script/core/request.md)、所选存储的 [k.file](../K-Script/file/index.md) 或 [k.media](../K-Script/core/media.md)，沿用 [后端约定](../Backend/index.md)。先复用站点已有文件管理代码和能力目录里确实存在的模板；不要假定存在通用上传模板、自动 tmp 清理或未注册的调度器。

1. **受管存储。** 文件归属、存储 key、业务引用及待回收信息跨请求/重启可恢复；可复用业务记录、现有资产表或上传批次，不强制每个功能新建通用资产中心。写入前建立可恢复记录或使用已有可靠的暂存机制，确保部分写入也可回收。优先一次确定存储 key，转正只改引用/状态，避免“重命名成功、记录仍指向旧路径”的孤儿文件窗口。
2. **服务端校验。** 校验数量/大小、实际文件类型与权限，路径由服务端生成，绑定/删除按服务端记录查归属，不接受客户端删除路径。私密附件使用已确认支持访问控制的存储与下载入口。使用已确认的文件 API，不为假想的输入类型编写多套解码/保存回退。
3. **成功绑定。** 在存储支持的事务/条件更新中协调绑定与清理；拒绝已过期、被回收或无权使用的文件。成功保存新引用后再释放旧引用，保存失败保留旧文件。共享文件仅在没有有效引用时删除；不能先查无引用、再无保护地删除，让并发保存绑定到已删文件。
4. **失败可回收。** 保存时上传也可能部分成功或中断，未绑定文件必须有到期回收依据。物理删除失败保留重试记录，不先删元数据。取消回调只用于尽早释放，关闭标签页或断网不能成为唯一清理入口。仅当功能实际生成缩略图、分片或转换文件时，纳入对应清理，不预建未使用的衍生文件系统。
5. **清理有调用方。** 使用已有服务端调度，或有节流/批次上限的请求触发清理，限定本功能受管文件并重查引用；失败记录不得持续占满同一批次而饿死后续回收。提前上传设置明确 TTL（无其他要求时通常为 24 小时）和配额。请求触发只承诺“到期后在后续操作中回收”，不能声称“24 小时内必定删除”。历史素材未出现在新表中不代表可删除。

保持当前数据策略：纯 mock 只做会话预览并如实说明，不能假保存却落盘永久文件；真实上传需持久化其引用/回收信息。以上是结果要求，不是必须逐项创建模块或 API 的清单。

## 源码回读重点

检查当前实现的实际路径：上传中点击保存、部分上传/业务保存失败、替换保留旧图、取消/离页、到期回收与删除失败重试。确认清理有真实调用方，失败后文件仍可追踪，绑定与清理不会互相破坏。只检查功能涉及的路径，不为不存在的分享、断点续传或转换生成代码；不添加额外浏览器验收门槛，未运行的行为如实标注。
