本 Skill 指导创建有辨识度、可用于生产的前端界面，避免泛泛的“AI 味”审美。实现真实可工作的代码，并格外关注审美细节与创意选择。

用户会提供前端需求：要构建的组件、页面、应用或界面。需求中可能包含用途、受众或技术约束等上下文。

## 设计思考

编码前，先理解上下文，并确定一个鲜明的审美方向：
- **目的**：这个界面解决什么问题？谁会使用它？
- **调性**：选择一个明确的极致方向：冷峻极简、极繁混沌、复古未来、有机自然、奢华精致、玩具般有趣、编辑部/杂志感、粗粝野兽派、装饰艺术/几何、柔和粉彩、工业/工具化等。可选风格非常多，这些只是灵感来源；最终设计必须忠于当前选择的审美方向。
- **约束**：技术要求（框架、性能、可访问性）。
- **差异化**：什么让它令人难忘？用户会记住的那一个点是什么？

**关键**：选择清晰的概念方向，并精准执行。大胆的极繁主义和克制的精致极简都可以成立，关键是有意识的设计，而不是单纯堆强度。

随后实现可工作的代码（HTML/CSS/JS、React、Vue 等），并满足：
- 达到生产级质量且功能可用
- 视觉上有冲击力、令人记住
- 具备清晰审美观点，并保持整体一致
- 每个细节都经过细致打磨

## 布局完整性与空间节奏

无论采用哪种视觉风格或设计系统，都要把布局完整性视为结果要求。设计系统可以决定间距尺度、密度特征、外壳比例和组件结构，但不能取消理解和操作当前界面所需的边界与分组。紧凑是一种有意识的节奏；由 reset、复制模板或缺少容器造成的零分隔不是密度。

- 每个可见业务区域都要有明确的间距归属，通过容器 `padding`、布局 `gap`，或有文档说明的 full-bleed 关系实现。不要依赖浏览器默认的标题、段落、列表或表单 margin。
- 全局 reset 移除 margin 和 padding 后，必须为自定义业务区域显式重建页面内边距、区块分隔、组件内边距和文本节奏。
- 保持可读的距离层级：同一个控件或条目内部的元素距离最近；相关控件和字段更远；Page Header、工具栏、内容、分页等独立区域之间再更远。
- 普通内容应与视口或 App 外壳保持内缩。贴边布局只用于有意设计的 full-bleed 媒体、画布、地图、时间线或同类表面，其叠加控件仍然需要安全内边距。
- 将相关的搜索、筛选、状态、选择和操作控件分组。空间和对齐本身就应体现分组关系，而不是只依赖边框、卡片或背景色。
- 确保文本、控件、媒体、浮层和动态状态在支持的视口尺寸下不会意外贴住或重叠。响应式压缩可以降低某一级间距、让分组换行或改变组合方式，但不能压塌语义分隔。

尽可能使用所选设计系统的 token。当来源没有提供可用的组合数值时，以下是起始范围，而不是必须照搬的像素值：

| 关系 | 常用起始范围 |
| --- | --- |
| 图标到标签及其他微关系 | 4-8px |
| 同一组件或操作组内部元素 | 8-12px |
| 相关字段、工具栏分组或卡片内容组 | 12-16px |
| Page Header、工具栏、内容及其他独立区域 | 20-32px |
| 普通页面内边距 | 移动端 16px；桌面端 24-32px |

在认为视觉实现完成之前，应脱离颜色和组件还原度，单独检查间距：

1. 只看空间和对齐，是否能识别 Page Header、工具栏、主内容、次内容和分页？
2. 如果移除边框、卡片背景和阴影，相关元素是否仍然能被看作一组？
3. 是否有任何非 full-bleed 内容意外贴住视口、外壳、相邻区域或其他控件？
4. 业务的核心材料是否保留了恰当的视觉优先级，尤其是在媒体、图库、审核、编辑器和内容密集型工作流中？

## 前端审美指南

关注：
- **字体排印**：选择美观、独特且有趣的字体。避免 Arial、Inter 这类泛用字体；改用能提升前端审美、有辨识度、出人意料且有性格的字体选择。用有特色的展示字体搭配精致的正文字体。
- **色彩与主题**：坚持一套连贯的审美。使用 CSS 变量保持一致性。主导色配合锐利强调色，通常比胆怯、平均分配的配色更有效。
- **动效**：用动画处理效果和微交互。HTML 优先采用纯 CSS 方案。React 中可用时使用 Motion 库。关注高影响力时刻：一次精心编排、带错峰出现（animation-delay）的页面加载，比零散的微交互更能带来愉悦。使用滚动触发和能制造惊喜的 hover 状态。
- **空间构图**：使用出人意料的布局、非对称、重叠、斜向流动、打破网格的元素。可以选择慷慨的留白，也可以选择受控的密度。
- **背景与视觉细节**：创造氛围和层次，而不是默认使用纯色。加入与整体审美匹配的上下文效果和纹理。可采用渐变网格、噪声纹理、几何图案、层叠透明、戏剧化阴影、装饰性边框、自定义光标和颗粒叠层等创意形式。

绝不要使用泛泛的 AI 生成式审美，例如被过度使用的字体族（Inter、Roboto、Arial、系统字体）、陈词滥调的配色（尤其是白底紫色渐变）、可预料的布局和组件模式，以及缺乏上下文特征的模板化设计。

要创造性地理解需求，做出出人意料但确实为当前上下文而设计的选择。任何两个设计都不应相同。要在浅色与深色主题、不同字体和不同审美之间变化。绝不要在多次生成中收敛到常见选择（例如 Space Grotesk）。

**重要**：实现复杂度要匹配审美愿景。极繁设计需要更精细的代码、大量动画和效果。极简或精致设计需要克制、精确，并细致关注间距、字体排印和微妙细节。优雅来自对愿景的良好执行。
